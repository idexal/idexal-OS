---
title: "Why sign in?"
description: "Why the published idexal Os desktop app asks you to sign in or start a plan on first launch, and what the account adds."
---

The idexal Os installers published by Idexal require an account. On first launch the app opens its own sign-in window: sign in, or start a subscription and choose a plan, and the workspace opens as soon as either is done. There is no anonymous mode in these builds. A build compiled from the source does not carry the gate, so developers can run it locally without a cloud account.

Once you are signed in, what needs the account and what stays local is:

| Works locally | Needs an idexal Os Cloud sign-in |
| --- | --- |
| Chat with your files in authorized folders | [Connections](/start-here/connect-your-stack/connect-services) your org shares, such as Gmail or Slack |
| [Your own models](/start-here/connect-your-stack/add-a-custom-llm), API keys, [ChatGPT sign-in](/start-here/connect-your-stack/sign-in-with-chatgpt), or [local models](/start-here/connect-your-stack/use-local-models) | [idexal Os inference](/start-here/connect-your-stack/idexal-os-vs-opencode-models) models |
| Local workspace skills | Adding skills and plugins from `Settings > Library`, team-shared skills, and [sharing your own](/start-here/do-work-with-it/publish-and-copy-a-skill) |
| [Custom MCP servers](/start-here/connect-your-stack/add-an-mcp-server) in a workspace | Automations |
| | [Dashboards](/dashboards/overview) and saved apps |
| | Cloud workspaces that keep tasks running while your computer sleeps |

Signing in to ChatGPT or another model provider is separate from signing in to idexal Os Cloud.
