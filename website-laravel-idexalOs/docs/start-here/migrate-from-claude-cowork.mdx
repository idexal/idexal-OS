You do not need to rebuild your setup to move from Claude Cowork to idexal Os. Start with one real task, bring over the capabilities it needs, and keep Cowork available until that task works end to end.

## Let your agent do the move

Paste this into Claude Code, or any agent that can run commands on your computer:

```text
Follow https://os.idexal.com/migrate.md to move my Claude plugins and skills to idexal Os.
```

The agent finds the plugin marketplaces you added and the skills you wrote, shows you what will move, imports the plugins you choose into your idexal Os organization, and lists what is left for you, such as connecting Gmail. Your own skills stay private to you. Running it again later picks up changes without duplicating anything.

You need an owner or admin account in your idexal Os organization to import plugins for everyone.

## What carries over

| From Claude Cowork | In idexal Os | What to do |
| --- | --- | --- |
| Local files and folders | Workspace files | Open the same folder or repository as an idexal Os workspace. |
| Skills you wrote | Private skills | `migrate` uploads them as skills only you can use until you share them. |
| Plugins from GitHub marketplaces | Organization plugins | `migrate` imports the ones you choose; their skills work right away and suggested connectors are optional. |
| MCP servers | Connectors and custom apps | Reconnect the server through idexal Os Connect or add its URL as a custom app. |
| Claude models | Anthropic provider | Add an Anthropic API key, or provision Anthropic centrally through idexal Os Cloud. |
| Scheduled tasks | Scheduled tasks | Recreate each schedule and verify its workspace, permissions, and output location. |

<Note>
  Conversation history does not transfer automatically. Keep any important instructions in workspace files or skills rather than relying on an old thread.
</Note>

## 1. Install idexal Os and open the same work

1. [Download idexal Os](https://os.idexal.com/download) for macOS, Windows, or Linux.
2. Create a workspace from the folder or repository you used with Cowork.
3. Ask idexal Os to summarize the workspace before changing anything. This confirms it can read the files you expect.

Your files stay where they already are. idexal Os does not require you to upload a duplicate copy before you can work with them.

## 2. Choose your models

idexal Os is model-agnostic. You can keep using Anthropic models, add another provider, or let your organization provision models centrally.

- To keep using Claude, follow [Add an Anthropic API key](/start-here/connect-your-stack/add-anthropic-api-key).
- To use ChatGPT, follow [Sign in with ChatGPT](/start-here/connect-your-stack/sign-in-with-chatgpt).
- For another provider, your own API key, or an AI gateway such as OpenRouter or LiteLLM, follow [Add a custom LLM or AI gateway](/start-here/connect-your-stack/add-a-custom-llm).
- To run a model on your own computer, follow [Use local models (Ollama, LM Studio)](/start-here/connect-your-stack/use-local-models).
- For Gemini or Google Vertex AI, follow [Use Gemini and Google Vertex AI](/start-here/connect-your-stack/use-gemini-and-vertex-ai).
- For a team-managed provider, follow [Managed LLM provider](/cloud/share-with-your-team/managed-llm-provider).

Your Claude subscription and Anthropic API billing may be separate. Confirm API access before removing Cowork from your workflow.

## 3. Bring over skills and plugins

idexal Os uses the same `SKILL.md` format. The prompt above moves them for you; by hand it is:

```bash
idexal-os-bootstrap login
idexal-os-bootstrap migrate plan
idexal-os-bootstrap migrate apply --plugin productivity,sales
```

After the move, for each skill you rely on:

1. Open the skill and check any file paths, app names, or environment variables.
2. Run the smallest task that should trigger it.
3. Confirm the output before importing the next skill.

See [Connectors, skills, and plugins](/start-here/do-work-with-it/skills-plugins-and-mcp) for how idexal Os organizes these pieces. For team distribution, see [Publish and copy a skill](/start-here/do-work-with-it/publish-and-copy-a-skill).

## 4. Reconnect apps and MCP servers

Credentials do not move between products. Reconnect each service so idexal Os receives its own authorized access.

- For Gmail, Calendar, Drive, Slack, Notion, Linear, and other managed services, use [Connect your services](/start-here/connect-your-stack/connect-services).
- For another remote or local MCP server, use [Add a custom MCP server](/start-here/connect-your-stack/add-an-mcp-server).
- For an organization-wide setup, use [Shared MCP connections](/cloud/share-with-your-team/shared-mcp-connections).
- To use the same skills and connections from Claude Code, Codex, or Cursor, [add idexal Os MCP in one command](/start-here/connect-idexal-os-mcp).

Test read-only actions first. Then test actions that modify data, such as sending a message or updating a record, with a disposable example.

## 5. Recreate schedules and browser tasks

For every recurring task, record:

- the prompt;
- its schedule and time zone;
- the workspace and files it can use;
- the connected apps it needs;
- where the result should be saved or sent.

Recreate one schedule at a time and run it manually before enabling recurrence. For browser-driven work, follow [Control the browser](/start-here/do-work-with-it/control-the-browser) and verify the target site while you are present.

## 6. Move a team without configuration drift

Do not ask every teammate to repeat your local setup by hand. In idexal Os Cloud, publish approved skills and connections once, assign them to the right teams, and apply desktop policies centrally.

See [Share skills and MCP servers with your team](/start-here/do-work-with-it/share-your-setup), then start with the [team quickstart](/cloud/team-quickstart), then review [desktop policies](/cloud/share-with-your-team/desktop-policies) and [members and roles](/cloud/members-and-rbac).

## Cutover checklist

- [ ] The same workspace opens and the agent can read the expected files.
- [ ] At least one model is connected and billing is understood.
- [ ] Each required skill triggers on a representative task.
- [ ] Each connector or MCP server is authorized and tested.
- [ ] Scheduled and browser tasks have been run manually once.
- [ ] Team capabilities are published centrally instead of copied machine by machine.
- [ ] Important Cowork instructions are saved in files or skills.
- [ ] Cowork remains available until the representative workflow passes in idexal Os.

Once the checklist passes, make idexal Os the default for that workflow and migrate the next one.
