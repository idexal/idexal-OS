<Note>
**Private alpha.** idexal Os in Slack must be enabled for your organization by a platform administrator. This guide is public; it does not grant alpha access. Contact [the idexal Os team](mailto:info@idexal.com) to request access. Slack's agent features must also be available in your workspace.
</Note>

Mention `@idexalos` in a channel or DM it to work with your own idexal Os connections and permissions. Each member connects their own Slack account. Installing the bot once does not sign everyone in.

## Who does what

| Who | What | Guide |
| --- | --- | --- |
| Slack and idexal Os administrator | Merge the manifest into the existing Slack app, install the bot, choose reply mode and channels. Once per workspace. | [Set up the Slack app](/slack/set-up-the-slack-app) |
| Every member | Connect your own Slack account once, then DM or mention `@idexalos`. | [Connect your account](/slack/connect-your-account) |
| Anyone | Fix a bot that is missing, silent, or never finishes. | [Troubleshooting](/slack/troubleshooting) |

## Ask your agent to set it up

Give an agent with browser or computer access this prompt:

```text
Set up idexal Os in Slack for my organization, using:
https://os.idexal.com/.well-known/agent-skills/set-up-idexal-os-slack/SKILL.md

Use our existing Slack app and Slack connector. Preserve existing user
OAuth scopes, redirect URLs, and MCP settings. Check private-alpha access
before making changes. Enable private replies. Ask me whether to limit
channels or allow all channels. Handle the configuration and verification
with my existing access, and bring me in for any required authorization.
Keep secrets out of chat and files. Test a real bot answer and report
what passed and anything still blocked.
```

The agent can inspect the setup, merge the manifest, verify event delivery, configure replies and channel limits, and test the bot. A Slack administrator authorizes installation; every member authorizes their own account. Your agent's tool permissions still apply.

## How replies and permissions work

- The person who mentions or DMs `@idexalos` is the only actor. The assistant uses that member's own Slack and connected-service access, not a shared account.
- Two members in the same Slack thread get separate idexal Os sessions.
- DMs and private rollout replies stay in the invoking member's DM. Channel replies are visible to the channel when private replies are off.
- If the assistant needs a permission decision, continue in idexal Os Web. Slack does not approve it for you.

This assistant builds on the [Slack MCP connection](/cloud/share-with-your-team/shared-mcp-connections#slack). Set that up first if your organization does not have one yet.
